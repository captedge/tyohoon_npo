# devlog: Help画面で英語表示時のみ出た謎の「透かし」— 正体はデバッグ専用のRenderFlexオーバーフロー警告だった

宣言2（記録の4分割）の③を担当。原因特定まで多くの往復を要し、かつ「外部要因（セキュリティソフト・不正アクティベータ等）を疑う調査」から「自プロダクトのコードを疑う調査」へ切り替えるタイミングの判断基準として、次回同種の調査（原因不明の見た目異常の切り分け）に再利用できるため退避する。

## 症状（ユーザー報告、2026-08-05）

`run_windows.bat`でのデバッグ実行中、特定の操作をした時だけ画面に黄色と黒の斜め縞模様＋赤字の文字列（当初は「ReLoved」、後に「RELOWED BY 0...」と判読）が透かしのように表示される。`build_release.bat`で生成したzip経由の同アプリでは同じ操作をしても再現しない。

## 調査の経過（誤った仮説を含む時系列）

1. **見た目の文字列だけを手がかりに検索**：「ReLoved」「リラブド」でWeb検索・プロジェクト全文検索（Grep）を実施したがヒットなし。pubspec.yamlの依存パッケージも純Dart・商用ライセンス無しで手がかりにならず。
2. **OpenJDK(java.exe)のメモリ使用量に着目**：タスクマネージャーで1.8GB使用の`java.exe`を発見し、フルパスを確認したところAndroid StudioのJBR（同梱Java実行環境）と判明。これ自体は「Android Studioが起動していた」という事実を示すだけで、透かしとの因果関係は未確認のまま、以下3の方向へ調査が進んでしまった。
3. **外部要因（セキュリティ）を疑う方向へ調査が寄り道**：「RELOWED BY」という文字列パターンから、Windows/Officeの不正アクティベータ「Re-Loader」との名称類似を手がかりに、マルウェア混入の懸念を提示。ユーザーの許可を得てWindows セキュリティ・タスクスケジューラ・タスクマネージャーを確認したが、いずれも異常なし（タスクマネージャー・タスクスケジューラは管理者権限で動作しておりcomputer-useから操作不能という制約にも遭遇）。
4. **ユーザーからの決定的な追加情報で自プロダクト要因に切り替え**：
   - 「build_releaseのzip版では同じ操作をしても出ない」→ **Debug限定**の現象
   - 「Helpメニューで英語にすると出る」→ 特定の言語状態でのみ再現
   - 「直前に言語切替ボタンを右上からここ（左上）に移動してから出るようになった」→ **直近の特定のUI変更が引き金**
   この3点が揃った時点で、外部要因ではなくアプリ自身のレイアウトが原因という仮説に切り替え、Flutterの「RenderFlexオーバーフロー警告」（黄黒斜め縞＋赤字で"A RenderFlex overflowed by N pixels..."と表示される、Dartの`assert`経由でデバッグビルドのみ描画される定番の警告）に思い至った。「RELOWED BY 0」は"...overflowed by 0.xx pixels"の一部が小さく回転した文字列を見間違えたものとして辻褄が合う。

## 原因（コード）

`typhoon_ship_tracker/lib/screens/help_screen.dart`のHelp画面AppBar：

- 言語切替ボタンが`leading`スロット（`BackButton()` + `OutlinedButton.icon`のRow）に配置され、`leadingWidth: 148`で幅固定。
- ボタンのラベルは`_japanese ? 'EN' : '日本語'`——日本語モード中は短い`'EN'`だが、英語に切り替えると`'日本語'`（全角3文字、'EN'よりかなり横幅が大きい）に変わる。
- `'日本語'`表示時、`BackButton` + アイコン + ラベルの合計幅が148pxをわずかに超えオーバーフロー。
- Releaseビルドはコンパイル時にアサーション（`assert`）が無効化されるため、この警告描画コード自体が実行されず症状が出ない——「Debug限定・Release非再現」という報告と完全に一致。

## 対応

`leadingWidth`を148→172に拡大し、`'日本語'`ラベル表示時でもオーバーフローしない幅を確保。ユーザーがWindows実機（`run_windows.bat`）で英語切り替え後も透かしが出ないことを確認済み（「でなくなりました：解決です」）。

## 教訓（次回同種の調査で使える判断基準）

- **「Debug限定で再現、Release非再現」は、外部要因（セキュリティソフト・システム全体のオーバーレイ等）よりアプリ自身のデバッグ専用コード（アサーション経由の警告描画等）を先に疑うべき、極めて強い一次情報。** 今回はこの情報がユーザーから出るまでOpenJDK・Android Studio・不正アクティベータ等の外部要因を広く探索してしまった。原因不明の見た目異常を報告された際は、早い段階で「Debug/Releaseどちらでも起きるか」「直前に何か変更したか」の2点を確認質問として投げるべきだった。
- **黄色と黒の斜め縞模様＋赤字は、Flutterの「RenderFlexオーバーフロー警告」の視覚的特徴として即座に想起できるようにしておく。** 次回似た報告（見慣れない縞模様・小さい回転した文字列）があれば、外部ツールより先にこのFlutter標準機能を疑う。
- **CJK文字（日本語ラベル）は英語ラベルより横幅が大きい。** 固定幅コンテナ（`leadingWidth`等）を設計する際は、両言語の中で最も幅を取るラベルを基準に余裕を持たせる（今回のように「一方の言語でだけ確認して問題なしと判断する」のは不十分）。
