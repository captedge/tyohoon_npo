# devlog: 地図オーバーレイ実装（グリッドラベル追従・カーソル座標表示・船アイコン向き）

宣言2（記録の4分割）の③を担当。いずれも3往復以上の試行錯誤ではないが、次回同種の実装（画面に追従するUI要素、逆投影変換、進行方向の角度計算）で再利用できる判断基準を含むため、往復回数に関わらずここに退避する（`docs/operation-rules.md`記録のルール5）。

## グリッドラベルの追従表示化（2026-07-27）

- **経緯**：緯度経度グリッドラベル（「20N」等）が、地図の論理キャンバス（`InteractiveViewer`がズーム/パンする対象）側にグリッド線と一緒に焼き込み描画されていたため、ズームイン・パンすると画面外に出て見えなくなる問題があった。
- **対応**：`_drawGrid`からラベルのテキスト描画を削除しグリッド線のみに変更（線自体は地図と一緒にスクロールするのが正しい挙動なのでそのまま）。ラベルは別オーバーレイ（`Positioned.fill`＋`AnimatedBuilder`）として実装し、`TransformationController`の現在の変換から各経線・緯線の画面上のX/Y座標を計算、画面内に入っていれば緯度ラベルは画面左端、経度ラベルは画面上端に固定表示する。
- **落とし穴と対応**：既存の`_zoom`/`_translation`状態はドラッグ操作の**完了後**（`onInteractionEnd`）にしか更新されないため、そのまま使うとドラッグ中はラベルが古い位置のまま止まって見える。`AnimatedBuilder`で`TransformationController`自体を直接listenする方式に変えることで、ドラッグ・ピンチ中もリアルタイムに追従するようにした。

## カーソル位置緯度経度の表示（2026-07-27）

- `MapBounds.toOffset`の逆変換`MapBounds.fromOffset`（Web Mercator逆変換、キャンバス座標→緯度経度）を追加し、往復変換が一致することをPython（sandbox）で事前検証。
- `MouseRegion`（`onHover`/`onExit`）でカーソルのビューポート座標を取得→現在の変換で地図座標に変換→`fromOffset`で緯度経度化→画面右下（度-分.小数第1位形式、例「31-15.5N 140-23.4E」）に表示。
- タッチ操作のみのデバイス（将来のスマホ展開時）では`onHover`が発火しないため、この表示は出ない。スマホ版でタップ位置表示が必要になれば別途検討が必要（要記憶）。

## 船アイコンの向き変更（2026-07-27）

- `MapPainter`に`nextWaypoint`（`LatLng?`）を追加し、現在の船位置から次のWP（変針点）への方位角を、投影後のキャンバス座標上で`atan2`により計算して三角形を回転。
- Web Mercatorは等角図法（局所的に角度を保つ）なので、この規模の地図であればキャンバス座標上の角度計算で実用上問題ない、という判断根拠。

## 教訓（次回同じ状況で使える判断基準）

- **画面（ビューポート）に追従させたいUI要素は、ジェスチャー完了後にしか更新されない内部状態ではなく、`TransformationController`のような変換の一次情報源を直接listenする設計にする。** 完了後更新の状態を流用すると、操作中だけ古い位置に見える不具合が起きやすい。
- **逆投影変換（画面座標→地理座標）を新たに追加する場合は、順変換とセットで往復一致をコードで機械的に検証してから組み込む**（今回はPythonで事前検証）。
- **等角図法（Web Mercatorなど）であれば、方位角のような角度計算は緯度経度上ではなく投影後のキャンバス座標上でシンプルに行って実用上問題ない**（対象範囲が限定的な用途なら特に）。
